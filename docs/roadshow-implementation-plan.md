# 路演前实现计划

更新时间：2026-06-23

## 成功标准

路演开始前需要达到这些标准：

1. 所有可公开代码和文档进入 GitHub，并排除 API Key、数据库、聊天记录、真实客户隐私。
2. 必要 API 可配置并能跑通核心链路。
3. 至少 3 名真实用户连续使用超过 3 天。
4. 能展示真实 bug、复现描述、修复状态和修复记录。
5. 第一次路演建议有记录、有取舍、有修改结果。
6. 有后期代码维护策略。
7. 爆贴分析后可以继续进入 AI 图片生成节点。

## 阶段 1：代码记录和仓库整理

目标：让项目代码、文档、配置模板都能被追踪。

执行项：

- 检查 `.gitignore`，确认不提交密钥、数据库、报告产物、微信文本和临时文件。
- 提交当前 Python Agent 代码。
- 提交配置模板、知识库和路演相关文档。
- 确认 `config/accounts.csv` 是否可公开；如果含真实账号信息，改成脱敏样例。

验收：

- GitHub 仓库能看到完整代码历史。
- 新成员可以根据 `README.md` 和 `config/settings.example.toml` 配置本地环境。

## 阶段 2：API 接入

目标：核心链路不再停留在占位数据。

必须接入：

- 小红书数据 API：补齐 `note_method` 和 `account_method`。
- 大模型 API：用于爆贴分析和业务号内容生成。
- 图片生成 API：用于封面图生成/改图。
- 企业微信或其他通知 API：用于日报/周报推送。

执行项：

- 真实密钥只写入 `config/settings.toml` 或服务器环境变量。
- 每个外部 API 都保留失败状态和错误信息。
- 关键模型调用后续进入 `model_call_logs`。

验收：

- 可以从一条小红书爆贴链接生成分析结果。
- 可以进入图片生成任务队列。
- 配置图片 API 后可以生成图片结果。

## 阶段 3：三个业务号内容生成

目标：学生号爆贴不只是分析，还要转化成业务号内容。

三个业务号建议：

- 业务号 A：论文/作业方向。
- 业务号 B：考试/挂科补救方向。
- 业务号 C：案例/转化方向。

每个业务号输出：

- 选题。
- 标题。
- 正文。
- 封面文案。
- 图片生成提示词。
- 发布建议。
- 风险提示。

验收：

- 同一条爆贴能生成 3 套不同业务号内容。
- 内容不能直接照搬原爆贴。

## 阶段 4：AI 图片生成节点

目标：在“业务内容生成”之后继续生成图片。

当前已接入的第一版节点：

- 命令：`xhs-agent generate-images`
- 数据表：`image_jobs`
- 数据表：`generated_images`
- 配置：`[image_generation]`

流程：

1. 从高互动笔记中读取爆贴标题和正文。
2. 按三个业务号生成封面图提示词。
3. 写入 `image_jobs`。
4. 如果图片 API 已配置，则调用图片模型。
5. 把图片链接或本地图片路径写入 `generated_images`。
6. 如果 API 未配置，则任务保留为 `pending`。

验收：

- 未配置图片 API 时，能看到待执行任务。
- 配置图片 API 后，至少生成 1 张封面图。
- 失败任务有错误原因。

## 阶段 5：3 人 3 天真实测试

目标：证明不是演示脚本，而是真实有人使用。

测试安排：

- 至少 3 名测试人员。
- 每人连续使用超过 3 天。
- 每天记录使用功能、问题、截图、严重程度、是否修复。

建议记录字段：

- 测试人。
- 日期。
- 使用功能。
- 操作步骤。
- 发现 bug。
- 严重程度。
- 截图/证据。
- 修复状态。
- 修复说明。

验收：

- 路演时能展示真实 bug 列表。
- 至少展示 1 个从发现到修复的完整案例。

## 阶段 6：第一次路演建议修改

目标：把反馈变成可追踪改动。

执行项：

- 建立 `docs/roadshow-feedback.md`。
- 每条建议记录是否采纳。
- 不采纳的建议说明原因。
- 采纳的建议写清楚修改内容和验证结果。

验收：

- 第二次展示时可以说明“根据第一次建议，我们改了什么”。

## 阶段 7：云端部署

目标：电脑不开机，系统也能自动工作。

建议第一版：

- Docker Compose。
- PostgreSQL。
- 一个 API/看板服务。
- 一个定时任务/Worker。
- 一个文件目录或对象存储保存图片和报告。

验收：

- 本地电脑关机后，云端仍可采集、分析、生成报告。
- 每天打开电脑能看到已分析好的结果。

## 当前缺口

- 小红书 Ark API 还缺具体 `note_method` 和 `account_method`。
- 图片 API 还缺真实 `base_url`、`api_key`、`model`。
- 业务号内容生成还没有独立入库表。
- 数据看板还没有实现。
- 3 人 3 天测试记录还没有开始。
